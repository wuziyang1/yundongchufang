# 健康档案理解与一人一策运动处方

青少年运动健康模型的第一版实现，覆盖两项能力：

- **健康档案理解** — 读取体检与体质测试结果，输出体质画像、短板排序、健康关注点，并识别缺失与矛盾字段生成追问
- **一人一策运动处方** — 基于档案与权威资料知识库生成 FITT-VP 结构化处方、周计划、风险提示；每个决定都标注依据的条目编号，可逐条回溯到资料出处与页码

前后端分离：后端提供 HTTP API，前端是一个单页应用，由后端一并托管。

```bash
cd backend && uv run uvicorn app.main:app --reload --port 8077
```

```bash
bash rag/scripts/milvus_up.sh
```

```bash
cd rag && uv sync
```

```bash
bash rag/scripts/run_index.sh
```

打开 http://127.0.0.1:8077 即是运动处方报告页。顶部选择学生档案后有两种方式：

- **★ 载入已有结果**：读取该学生最近一次保存的画像与处方，**3 毫秒出结果**，不调用模型。
  下拉里带 ★ 的学生表示已有结果可加载：既包括脚本预生成的（默认 5 份），也包括
  在页面上实时生成过的——画像与处方各自落盘到后端留档目录，刷新页面后仍可再次载入。
- **重新生成**：实时调用模型。生成期间右侧滑出「AI 生成过程」面板，模型的思考过程
  按 Markdown 实时渲染（结构化 JSON 不展示原文，只显示写入进度），按钮同时变为
  「■ 停止生成」，可随时中断。耗时取决于 `LLM_THINKING`：关思考约 80 秒，
  开思考（当前默认，输出思考内容供展示）约数分钟。

除内置档案外，点工具条的 **「✎ 自行录入档案」** 可展开录入表单，填写基本信息、体测成绩、
健康状况与运动习惯；点「保存档案并生成处方」后，档案会追加进
`backend/app/data/mock_students.json`（学号由服务端生成，`CU` 前缀），
该学生随即出现在下拉列表中，并直接走画像 + 处方生成流程。

报告页是纯 HTML 流式页面：宽度跟随窗口（上限 1180px）、高度随内容增长，窄屏时分栏自动折行，
手机上也能通读。

| 路径 | 用途 |
|---|---|
| `/` 、`/report` | 运动处方报告（流式自适应页面） |
| `/profile` | 健康档案理解报告：第一阶段画像各字段的报告页，可从处方报告页工具条「📋 档案理解报告」跳入 |

### 接入模型

当前接的是**智谱 Anthropic 兼容端点**，模型 `glm-5.3`。配置在 `backend/.env`（已 gitignore）：

```
LLM_PROVIDER=anthropic_compatible
ANTHROPIC_COMPAT_BASE_URL=https://open.bigmodel.cn/api/anthropic
ANTHROPIC_COMPAT_API_KEY=你的密钥
ANTHROPIC_COMPAT_MODEL=glm-5.3
```

四种 provider 可切，业务代码不感知：

| `LLM_PROVIDER` | 端点 |
|---|---|
| `anthropic_compatible` | 智谱 Anthropic 兼容端点 `/api/anthropic` |
| `zhipu` | 智谱 OpenAI 兼容端点 `/api/paas/v4/` |
| `openai_compatible` | 本地部署或其他 OpenAI 兼容服务，交付期用这个 |
| `mock` | 离线占位假数据，返回带 `[MOCK]` 标记，仅供前端联调 |

**GLM-5.3 是思考模型**，这一点对配置有实际影响：

- 开启思考时约 **80% 的输出 token 花在思考上**，而思考内容你永远看不到。实测同一份档案：

  | 阶段 | 思考开 | 思考关 |
  |---|---|---|
  | 画像 | 147.9s（出 10231 tok，思考 8260） | 28.8s（出 2021 tok） |
  | 处方 | 255.9s（出 15843 tok，思考 12389） | 55.2s（出 3404 tok） |
  | 合计 | 403.8s | 84.0s |

  两者生成速度相同（约 62-70 tok/s），差异全部来自 token 量。**默认 `LLM_THINKING=false`**，
  内容质量实测接近；需要更严谨推理时改为 `true`。
- `glm-5.3-flash` 反而更慢（画像 259.2s）：它产出更多思考且速度更低。flash 是便宜，不是快。
- thinking 消耗的 token 计入 `max_tokens`，默认 65536 为此预留余量。
- Anthropic 端点返回的 `content` 是块列表，provider 只取 `type: "text"` 的块；流式只透出 `text_delta`。
- anthropic SDK 2.6 起 `messages.create/stream` 不再接受顶层 `temperature`，provider 经 `extra_body` 透传。
- 单次调用耗时在分钟级，`LLM_TIMEOUT` 默认 300 秒。

## 工作流程

```
原始健康档案
     │
     ├─ [代码] 急症关键词熔断 ────────────► 命中即返回固定就医模板，不调用模型
     │
     ├─ ① LLM：档案理解（不使用知识库）
     │     输出 体质画像（基础评价、六维、综合评价、健康关注点）
     │
     ├─ [代码] 知识库检索（Milvus，处方专业依据的唯一来源）
     │     · 体质评定：取出国标评分表，按性别、年级、成绩查表 → 每项得分与等级（S 条目）
     │     · 权威资料摘录：把处方拆成若干检索主题，逐个检索并把关相关性（E 条目）
     │     · 可选动作：训练手册的练习条目，按学段、器材、单人可做筛出候选
     │     · 查不到针对性资料的主题记为「知识库未覆盖」
     │     知识库不可用 ─────────────────► 报错，不生成处方
     │
     └─ ② LLM：处方生成（流式）
           输出 FITT-VP + 周计划 + 风险提示，每个决定带依据编号（evidence_ids）
                │
                ├─ [代码] 校验：动作编号在候选集内、引用的编号真实存在、FITT-VP 六项各有摘录依据、
                │          周计划完整、训练日与时长不超上限
                │          ─► 不通过则带问题清单重生成一次
                │
                └─ [代码] 回填：动作详情与出处页码、每条摘录被处方哪些位置引用、
                           知识库未覆盖的问题、知识库指纹
```

两次 LLM 调用，其余是代码。控制流由代码决定，不由模型决定。

### 知识从哪里来

处方的专业依据**只来自 Milvus 知识库**（`rag/` 离线入库的国家标准、指南、训练手册、文献）。
`backend/app/data/` 下的 `exercises.json`、`knowledge.json` 是早期由 AI 整理的动作库与知识卡片，
文件保留，但已不参与检索与生成。

只把 PDF 切片存进向量库、按相似度取几条拼进 prompt 是不够的，会遇到下面这些问题；每一条都有对应的处理：

| 只靠向量检索的问题 | 处理 |
|---|---|
| 评分表靠相似度检索不出正确的行，模型读表还会读错（实测把 BMI 25.1 的六年级女生判成「超重」，表里 ≥23.7 即「肥胖」） | 评分表入库时标为查表数据，在线整张取出，**代码查表**，结论作为确定事实交给模型 |
| 一句话检索一次，回来的总是同一段「每天运动 60 分钟」，强度、抗阻剂量、体重管理、伤病注意事项各自需要的依据一条也没有 | 按「处方要做的每个决定」拆成检索主题，**逐个主题检索** |
| 「哮喘」「肥胖」这类必须字面命中的词，向量相似度召回不稳 | 向量 + **BM25 关键词**两路召回（Milvus 内置） |
| 相似度区分不了「话题相近」和「有答案」：知识库里没有踝扭伤的内容，讲热身的段落照样排前面 | 候选交给**重排模型**打分把关，低于阈值的不要 |
| 知识库没覆盖的问题，模型会凭记忆补一个像模像样的结论 | 如实记为「**知识库未覆盖**」，明确告诉模型不要编，结果里单列出来交给审核人 |
| 资料没有学段信息，高中的要求可能用到小学生身上 | 每份文档登记**适用学段**，检索时过滤 |
| 原文段落不能当动作库用：没有编号、类别、器材 | 训练手册的「练习N」入库时整理成**动作条目**，代码按学段、器材、单人可做筛出候选 |
| 知识库里有英文文献，中文问题对英文段落召回、打分都偏低 | 相关主题另带英文查询，重排问题附英文说法 |
| 无法证明模型用了知识库 | 模型在每个决定上写**依据编号**，代码核对编号真实存在；每条摘录被哪里引用随处方留档 |
| 知识库连不上时悄悄退回「只靠模型记忆」 | 知识库不可用时**不生成处方**并说明原因 |

自检（不调用大模型，打印一份处方会从知识库拿到的全部材料）：

```bash
cd backend && uv run python -u scripts/check_kb.py BJ2025200148
```

### 检索主题

每份处方固定检索：每日活动量与每周频率、运动强度的评估与控制、运动负荷与适宜心率范围、运动类型的搭配、
常见的有氧与抗阻运动项目、常见身体活动的强度、抗阻训练的组数次数与频率、进阶与负荷递增、
单次锻炼的结构与各部分时长、运动安全与损伤预防、户外活动的环境条件。

按学生情况追加：BMI 评定不是「正常」时的体重管理；国标得分最低的 3 项短板各一个；
慢病、伤病史、近期症状、脊柱与视力筛查异常各一个。

代码里只定义「要查什么」（`app/services/kb/evidence.py`），不包含任何专业结论。

### 相关性把关与阈值

默认用智谱 `rerank`（与嵌入共用密钥）取原始分，阈值 17；针对个人的主题（短板、健康状况）从严，再加 1。
在内置 20 份档案上实测：有针对性资料的主题最高分都在 18.2 以上，没有的最高 17.7。
换重排服务或嵌入模型后分值尺度不同，须重新标定：

```bash
cd backend && uv run python -u scripts/check_kb.py --all
```

重排不可用时自动退回向量相似度把关（`KB_DENSE_MIN_SCORE`），处方照常生成，结果里会注明本次是降级把关。

### 知识库现在缺什么

「未覆盖」直接反映知识库的缺口。内置 20 份档案里，22 项健康状况只有哮喘查得到资料，
膝踝伤病、血压偏高、脊柱侧弯、贫血、近视都没有；体测短板里仰卧起坐、引体向上、坐位体前屈、跳绳也没有
专项提升方法的文字资料（只有训练手册里的相关动作）。小学、初中的课程标准，营养与膳食，体重管理的专门指南同样缺失。
补充相应资料入库后重新生成即可覆盖，不用改代码（新增资料的步骤见 [rag/README.md](rag/README.md)）。

### 代码约束

LLM 真正不可靠的地方才用代码兜住，其余交给模型：

1. **急症熔断** — 档案中出现胸痛、呼吸困难、晕厥等关键词时直接返回固定模板，不进模型
2. **国标评分** — 体测成绩的得分与等级由代码按知识库里的评分表查表，模型不得改判
3. **动作绑定** — 目录动作只能用候选集里的编号；候选集按学段、器材、单人可做由代码筛出。
   目录里没有的常规活动（快步走、慢跑等），名称要能在摘录原文里找到，找不到的标「待核实」
4. **依据核对** — 引用的编号必须是本次检索到的条目；FITT-VP 六项每项至少引用一条摘录

禁忌判断仍由模型根据档案与动作说明给出，没有硬编码的禁忌规则库；风险筛查由独立的风险筛查服务承担。
原先动作库里的「风险标签」随 AI 整理的动作库一并停用——知识库的训练手册没有这类标注，
模型按动作的名称、功能、用量说明判断身体负荷。

|---|---|---|
| GET | `/api/v1/meta` | 版本、模型、知识库状态 |
| GET | `/api/v1/students` | 学生档案列表（摘要，含录入追加的档案） |

| GET | `/api/v1/pregenerated` | 有留档结果可载入的学生清单（画像 ∪ 处方） |
| GET | `/api/v1/pregenerated/{id}` | 从 profiles/ 与 prescriptions/ 拼装读取留档结果（不调用模型） |
| GET | `/api/v1/knowledge-base` | 知识库状态：是否可用、指纹、文档清单、相关性把关方式 |
| GET | `/api/v1/exercises` | 知识库里的全部动作条目（训练手册的练习） |
| GET | `/api/v1/exercises/{id}` | 单个动作详情，如 `JK002` |
| POST | `/api/v1/profile:analyze` | 档案 → 体质画像 |
| POST | `/api/v1/prescription:generate` | 画像 + 请求参数 → 运动处方（SSE 流式） |

### 画像

```bash
curl -s -X POST http://127.0.0.1:8077/api/v1/profile:analyze \
  -H 'Content-Type: application/json' \
  -d "{\"record\": $(curl -s http://127.0.0.1:8077/api/v1/students/BJ2025090314)}"
```

返回 `{"emergency": null, "profile": {...}}`。命中急症熔断时 `profile` 为 null、`emergency` 有值。

### 处方

`POST /api/v1/prescription:generate`，请求体 `{record}`。以 SSE 返回：

| 事件 | 含义 |
|---|---|
| `status` | 进度说明：开始生成、知识库检索结果（主题数、摘录数、未覆盖数、候选动作数） |
| `thinking` | 模型的思考过程（开启思考时） |
| `token` | 模型原始输出片段，供前端显示进度 |
| `retry` | 触发了一次重生成，data 为问题清单 |
| `result` | 最终处方 JSON |
| `emergency` | 急症熔断 |
| `error` | 生成失败，含知识库不可用 |
| `done` | 流结束 |

处方 JSON 里由代码填写的依据链路：

| 字段 | 内容 |
|---|---|
| `assessment` | 体质评定（S 条目）：每项体测成绩的得分、等级、查表依据原文、出处页码 |
| `evidence` | 权威资料摘录（E 条目）：出处、原文、因哪些主题被检索到、被处方哪些位置引用（`cited_by`） |
| `knowledge_gaps` | 知识库未覆盖的问题 |
| `knowledge_base` | 生成时的知识库状态：指纹、文档清单与各自 MD5、各检索主题的覆盖情况与最高相关性分数 |
| `exercise_details` | 被引用动作的功能、起始姿势、练习步骤、指导提示、安全事项、原书用量、出处页码 |
| 各处的 `evidence_ids` | FITT-VP 六项、强度监测、每天的安排、每个条目、风险提示、运动禁忌所依据的条目编号 |
| 条目的 `verified` | 常规活动的名称没有在任何一条摘录里找到时为 `false` |

## 数据契约

档案分三层，前两层沿用现有系统的原字段名与字符串格式，便于对接；第三层是安全判断必需的扩展。

| 层 | 字段来源 | 说明 |
|---|---|---|
| `physical_exam` | 体检结果表 16 字段 | `SG` `TZ` `FHL` `ZYSL` `JZ` 等，全部字符串，允许空 |
| `fitness_test` | 体质结果表 16 字段 | `WSMCJ` `LDTYCJ` `ZWTQQCJ` `YQMCJ` `YTXSCJ` 等 |
| `health_profile` | **扩展** | 慢病、用药、伤病史、近期症状、生命体征 |

扩展层是必须的：原两张表没有伤病史与禁忌相关信息，而这些是安全判断的唯一输入。实际对接时这部分由前端问卷采集。学生不提供处方需求——锻炼目标由模型从档案与国标评分推导，训练量依据知识库摘录确定，动作候选按普遍可得的器材（`KB_EQUIPMENT`，默认瑜伽垫、标志线、标志碟、锥形筒）过滤，徒手动作始终可用。

体测项目按学段设置不同（小学无立定跳远与中长跑、男生无 800 米与仰卧起坐等），因此相应字段为空属正常，prompt 中已说明，不会被误判为数据缺失。

每份处方都带上所用的 prompt 版本、模型与知识库指纹；增删或替换知识库里任何一份资料，指纹都会变。

### 生成结果的保存与再次加载

所有生成结果只落两个留档目录 + 一份熔断记录，同一学号重复生成直接覆盖，均以 `{学号}.json` 命名：

| 位置 | 内容 |
|---|---|
| `app/data/profiles/{学号}.json` | 最近一次生成的体质画像 |
| `app/data/prescriptions/{学号}.json` | 最近一次生成的运动处方 |
| `app/data/emergency_records.json` | 学号 → 最近一次急症熔断记录（就医提示） |

线上实时生成与脚本预生成共用这套留档。急症熔断时**不清除**已有的画像与处方文件，
只把熔断记录写入 `emergency_records.json`；此后前端选中该学生自动展示的就只有
就医提示（不返回旧画像与处方，避免误用），该学生也会带 ★ 出现在列表中。
画像或处方重新生成成功时自动解除熔断，恢复正常留档展示。
`/api/v1/pregenerated` 系列接口从上述位置拼装返回。
两个留档目录与熔断记录文件均已 gitignore。

### 预生成结果

`scripts/pregenerate.py` 调真实模型为学生生成画像与处方，成功后由服务层覆盖留档到
`app/data/profiles/` 与 `app/data/prescriptions/`（与线上实时生成共用同一路径）：

```bash
cd backend && uv run python -u scripts/pregenerate.py
```

默认生成 5 份（李沐阳、陈若溪、王子轩、黄俊豪、刘星月），覆盖不同学段、性别、体能水平与约束类型。
`--all` 生成全部档案，也可指定学号。**串行执行**：并发会触发上游限流，单次调用会从 1 分钟拖到十几分钟。

模型、prompt 或知识库改动后这些结果即过期，需重跑；留档里记录了 `generated_at` 与知识库指纹便于判断。
知识库接入之前生成的处方没有依据链路，报告页会提示重新生成。mock 模式的占位结果不落盘。

## 已验证与未验证

知识库改造后已验证：

- 入库：6 份资料 593 个切片，其中动作条目 250 个（训练手册的练习 1–250 全部识别）、查表数据 45 块（16 张单项评分表）
- 国标评分：20 份档案逐项查表；彭语嫣的 7 项与另外 5 份档案各抽查的 1 项，逐一对照评分表原文一致
- 检索：20 份档案的主题覆盖情况（`check_kb.py --all`），固定主题全部有资料，健康状况只有哮喘被判为有资料
- 真实模型（glm-5.3，关思考）生成彭语嫣的处方约 60 秒、一次通过校验：BMI 判为肥胖，首要短板为得分最低的仰卧起坐，
  FITT-VP 六项全部带摘录依据，动作全部来自训练手册，小腿酸痛与近视如实标注「知识库暂无针对性资料」；
  另跑了李沐阳（哮喘 + 踝伤）、黄俊豪（无短板）、马天宇（血压偏高）三份，均 30–40 秒一次通过，没有待核实的活动
- 失败路径：Milvus 连不上时报错不生成；重排关闭或请求失败时降级为向量相似度把关
- 报告页：国标得分徽标、依据角标与跳转、动作详情与出处、未覆盖提示、旧留档的兼容展示

**仍需专业人员判断**：处方的科学性与安全性（禁忌判断由模型给出）、相关性阈值在更多档案上的表现、
知识库未覆盖问题的处理是否足够保守。

## 本版不包含

按第一版范围约定，以下内容未实现：

- 风险分层规则库与禁忌症规则表（风险筛查由独立的风险筛查服务承担，代码只做关键词熔断）
- 复测调整与处方版本对比
- 人工审核流转（处方生成后直接返回，无审核状态机）
- 指标评测集与自动评分
- 画像阶段接入知识库（档案理解仍由模型直接判断体质等级，与处方阶段的国标查表结果可能不一致）
- 饮食建议（知识库里没有营养与膳食方面的资料）
- 数据库（mock 档案为 JSON 文件，处方结果不持久化）
